# 基础商业 Skill 架构

这份文档定义的是一个可持续扩展的基础商业 Skill 骨架。

它的目标不是一次性覆盖所有能力，而是先建立稳定的结构，让后续的选品、定价、店铺拆解、推送、复盘都能挂在同一套框架下。

---

# 一、设计原则

1. 先统一输入，再统一分析，再统一输出。
2. 所有模块都必须服务于“商业决策”。
3. 所有结果都要可复用、可追踪、可复盘。
4. 先做最小可用骨架，再按实际工作流扩展。
5. 任何新能力都应该是“加模块”，而不是“改地基”。

---

# 二、基础架构

一个基础商业 Skill 建议分成 5 层：

## 1. 输入层

负责接收用户的核心任务信息。

标准输入项：

- 目标市场
- 目标平台
- 目标类目
- 价格带
- 用户模式
- 约束条件
- 输出偏好

这一层的作用是把问题说清楚，避免后面所有判断都建立在模糊前提上。

## 2. 发现层

负责从市场中找出候选对象。

常见来源：

- 内容平台
- 电商平台
- 对标店铺
- 历史数据
- 用户评论

这一层的任务不是下结论，而是收集“可分析对象”。

## 3. 分析层

负责把候选对象做结构化拆解。

分析维度建议统一为：

- 需求强度
- 购买意图
- 内容传播性
- 利润空间
- 无货源适配度
- 风险等级
- 趋势阶段

这一层是 Skill 的核心判断层。

## 4. 决策层

负责把分析结果转换成执行建议。

标准结论建议统一为：

- 优先测试
- 观察后测试
- 谨慎进入
- 不建议进入

这一层要给出“为什么”和“下一步做什么”。

## 5. 运营层

负责沉淀日常执行过程。

常见产物：

- 日报
- 去重表
- 推送表
- 价格表
- 复盘表

这一层决定这个 Skill 能不能长期用，而不是只做一次分析。

# 三、推荐模块

基础商业 Skill 先保留下面这些模块，后续再追加：

## 核心模块

- 市场调研模块
- 选品分析模块
- 价格核算模块
- 风险排查模块
- 上架标题模块

## 运营模块

- 每日推送模块
- 去重模块
- 店铺拆解模块
- 复盘模块

## 扩展模块

- 类目专项模块
- 国家专项模块
- 竞品跟踪模块
- 素材脚本模块

---

# 四、统一数据结构

建议所有模块输出都尽量遵守同一套数据结构。

## 基础字段

- 名称
- 类目
- 市场
- 来源
- 价格
- 成本
- 利润
- 风险
- 推荐等级

## 决策字段

- 是否可测
- 是否可推
- 是否可复制
- 是否适合无货源
- 是否适合新手

## 运营字段

- 去重标识
- 推送日期
- 推送渠道
- 备注

---

# 五、推荐输出结构

所有商业类 Skill 的输出建议固定成 4 段：

1. 本次结论摘要
2. 数据或候选清单
3. 评分与判断
4. 下一步动作

这样后续无论是选品、店铺拆解还是定价，输出都能保持一致。

---

# 六、当前项目里的落地映射

当前这个项目已经按基础架构拆成了以下部分：

- `docs/`：架构、模板、案例、词库
- `scripts/`：生成 Excel、更新定价表、维护去重逻辑
- `data/`：主定价表
- `outputs/`：输出文件

这已经足够作为一个基础商业 Skill 的 MVP 骨架。

---

# 七、后续扩展原则

以后新增模块时，建议遵循这条规则：

1. 先定义这个模块属于输入、发现、分析、决策还是运营层。
2. 再定义它需要哪些字段。
3. 最后再决定它输出到哪个 Excel 或文档。

这样整个 Skill 不会长乱。
